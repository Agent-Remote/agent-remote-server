# 迁移过期比较与替代尝试

本协议延续原设计的完整目录原子性，不把 epoch 失效当普通 head 竞争。
原始 preparation 的受理 JSON、比较输入、人工树及选择始终保留。resolve 先按用户键
重放原回执，再检查计划版本；发现旧目标时忽略本次选择，也不把旧选择或人工内容授权
转移给新尝试。dry-run 只说明旧比较失效和拟采取的行为，不能创建替代记录或推进 head。

## 持久化关系

迁移 0038 为 `skill_branch_preparations` 增加可空的 `recomputed_from_id`、`replacement_id`
及 `superseded_reason`。两个身份引用都由 user/account 复合外键绑定。同一原尝试最多有一个
直接重算子尝试，禁止自身引用。replacement 或失效原因只能出现在 superseded 记录上。
旧数据保持空值，不从时间、摘要或今天的 head 猜测历史关系。含任一新增信息时降级在
修改 schema 前拒绝；无新信息时允许回退并保持所有原始行和 JSON。

新尝试保留原安装、源/目标分支、全部 epoch、确切 source checkpoint 和成功增量基线。
只更新今天的目标 current、完整账户目录及同身份配置代数。来源同纪元新 head 不替换
原始 incoming；必要的完整链接上下文只来自原 source checkpoint，绝不来自实时 source head。
新尝试与旧记录失效、替代链接、可选原子发布及本次回执在同一用户写锁和保存点内提交。

## 重算与终止

- 同纪元目录或目标 head 改变：从保存输入与今天 current 重新三方比较。关联范围仍需
  完整显式选择；独立且可自动合并的结果可以发布，冲突则创建没有任何选择的新计划范围。
- initial/older 不自动导入较新版学习状态。它们按自己的准备语义重新尝试目标内容与当前
  目录组合；只有用户对新冲突明确选择 incoming 才能导入保存来源。
- library generation 改变：向前/初次/旧版准备必须仍选择同一个启用的目标版本，否则
  superseded。显式 incremental 的源/目标选择独立于 pin，但不能跨安装身份和 epoch。
- 源/目标或完整 directory epoch 改变、源/目标安装被移除/失效：旧记录只失效和保留。
  关联成员按下文真实写入集合判断；账户级 reset/restore 取消不直接证明所有关联项失效。
- 更新的成功迁移改变增量基线：旧记录指向该替代成功记录，不能将成功基线退回旧来源。
- 已失效原尝试的新请求只返回已有替代关系；不能在同一个原尝试下创建分叉。

查询、摘要、解决回执必须分别展示原始结果、当前状态、失效原因和可用的 replacement ID。
如果不存在可继续的替代尝试，replacement 为空，并明确说明恢复/重新迁移需要独立命令。
新的准备/迁移自动受理入口仍须通过其原有规则与 CAS，不因本协议修改有效使用账本。

## 关联写入与生命周期失效细化

重算不会继承旧选择。关联纪元检查只覆盖旧比较中确实改动的关联成员：已有完整计划以
其候选相对保存目录的差异为准；尚未形成完整候选时，以保存 incoming 相对保存目录的
差异为保守边界。仅链接但原样保留的成员不算写入，可以在新比较中采用今天的完整目录
上下文。曾实际改动的成员失去来源身份或纪元时，整次旧尝试终止，不自动拆分发布。
新比较的完整 incoming 仍沿原 source checkpoint 验证历史身份和纪元；字节相同不提供
跨 reset、重装或版本替换的授权。新比较不转移任何人工上传授权。

库变更在配置事务中主动取消被移除或跨安装纪元的目标迁移；非 incremental 准备还需
按各账户真实有效规则取消不再启用或不再选中原目标版本的记录。独立账户规则、独立安装
以及仍有效的显式增量方向不被粗粒度取消。关联成员失效仍在重算/候选检查时精确判断。
成功的 forward/incremental 迁移在发布保存点内取消同账户、同安装、同方向、同全部纪元
的旧冲突并指向该成功记录。重算的直接父尝试由原有 CAS 设置唯一替代，不能提前批量取消。
先前仅被账户级 reset/restore 取消、仍匹配上述全部纪元且尚无替代的记录也可关联该成功。
已有替代关系保持不变，真实源/目标或目录新纪元的成功不能取代旧纪元计划。
initial/older 没有成功序号，也不能用作增量基线替代。回执落库失败必须回滚这些失效变更。

生命周期增量新增 33 个回归场景：11 项关联写入精度、17 项主动生命周期、3 项方向/纪元
