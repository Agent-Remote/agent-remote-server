# Skill state prune：公开入口接入约束

当前已提供内部保活分析、时钟、比较/checkpoint 退役、目录整理、只读空间投影及实际
内容回收 worker。整理、退役和回收可在同一保存点内执行，详见 `skill-prune-projection.md`。
账户/单项范围和完整候选组现由内部 `SkillPruneService` 处理，固定截止、可执行组、
整理等待及 0044 生命周期续扫归属见 `skill-prune-candidates.md`。
公开 Server 预览、签名分页确认和 0045 不可变回执已按 `skill-prune-api.md` 接入。
本文保留跨端接入约束；CLI 命令、完整显示和断线恢复仍须接入，不能据此宣称端到端完成。

## 精确请求与预览

复用现有 `SkillStateSelector` 的 item/完整账户目录范围。账户必须明确；单项来源使用
稳定身份解析，不以目录名推断来源或安装纪元。普通 prune 只选择真实截止已到的状态历史；
all-unreferenced 只越过等待。包版本和本地初始版本不能被 state prune 顺带删除。

用户确认的完整结果必须同时列出：将失去恢复能力的精确历史 checkpoint、连带退役的
比较身份、目录/分支等价 head 变化、关联依赖阻断、仍在保留期的旧视图和确实仍有内容
引用的对象。不能把所有 unprotected 行称作可删除候选，不能只比较名称或 generation。

内部 CompactionPlan 包含完整清单，可用于服务内重建/比较；不能原样作为公共请求或
CLI 恢复日志。当前 CLI 精确请求日志单条上限 4 MiB，公开确认请求应保存明确选择与
规范计划摘要，Server 在锁内重新计算全部内容/身份前置条件。摘要覆盖原始头、纪元、
库代数、来源、成员、原/结果树摘要、保留资格、连带退役和预览的空间影响。不能只签名
一个可以后来重新解释的 skill 名称。展示或分页不得省略未确认的失去恢复能力清单。

CLI 复用 `local_state/skill_commands.rs` 中按 Server/用户绑定的原请求日志、一次确认和
原 key/operation ID 查询。断线或 Ctrl-C 后先查原受理，不能重新 preview 后生成新键，
也不能在未知受理时用当前 head 替换原确认。Server 返回原不可变受理结果与当前删除进度，
不能把最初的 accepted 改写成仿佛一开始就完成。

## 整理后的资格与同一保存点

公开预览必须计算整理后的保护闭包，不能在真实数据库中暂时交换 head 来实现 dry-run。
假设替换只作用于计划中的当前 head 和成员；原 snapshot、冲突、精确增量基线及未退役
历史仍指向原身份。特别是等价 head 替换后，旧基线可能继续保护旧 checkpoint 和完整树。

普通请求不能把新近解除保护的等价旧视图按旧创建时间立即退役。显式提前也只能退役
整理后确实失去全部硬保护、且所有保留历史依赖已同时处理的身份。内部整理与完整历史
退役现均使用全索引安全预算。公开账户范围实现仍必须处理完整候选和关联依赖，不能
静默截断成第一批成功或破坏关联原子性。

受理、计划复核、等价视图发布、全部历史内容引用退役、实际逻辑配额结算与持久化删除
任务应在同一用户锁和业务提交边界内完成；任何前置失败不能留下半次 head/expired
变化。原请求先查不可变回执，再访问可能已退役的输入，以支持断线恢复。

## 物理内容与生命周期

树只有在所有真实保留引用解除后才可移除对象引用。对象按 package/state 分类结算，
物理文件按 user/digest 共享；另一分类、另一个账户的保留状态或活动上传仍引用同一
文件时，不能删除物理文件或虚报释放空间。未绑定历史身份的完整上传树也需要明确的
等待和授权语义，不能凭数据库中暂时没有 checkpoint 就立即删除。

物理删除必须在持久化 deleting 标记提交之后执行，使用可重试任务。Worker 崩溃、
删除失败和已删除但尚未记账都必须可收敛。新的 begin/put/complete 和已有摘要引用入口
必须共同拒绝复用 deleting 对象，直到删除终态和重新完整验证。租约截止与复用检查都
以固定用户锁内的真实时间/身份为准，不能先删文件再指望数据库回滚恢复内容。

这些任务与实际 Node-only export、runtime materialization/finalization、真实 Native 和
Docker Sandbox 验收及部署恢复一起，仍属于完整 Skill 管理器的未完成范围。

## 整理保护投影实现边界

内部整理服务已提供精确计划重验后的只读保护投影。投影仅替换当前分支 head 与账户
目录 head，补充新目录/单项的虚拟身份、成员和树对象边；全部原始 checkpoint、成员、
快照、冲突和增量基线边保持原样。虚拟身份只在预览内有效，不作为可提交的 checkpoint。
实现不得修改 ORM 行、刷新写入或临时交换真实 head。新目录使用结果清单的真实摘要，
因此既有相同摘要、跨账户共享对象和原始历史保护仍合并到同一内容节点。

投影同时给出原有历史的预计保护与等待信息。保护刚消失的历史从本次固定分析时间起
预计等待，而非沿用创建时间或陈旧 release 值；仍保护的历史没有可用截止。未知旧时钟
不补造。预计时间不是持久化时钟，受理必须重验并由真实事务启动等待。此入口不模拟
历史退役，不绕过保留历史依赖，也不报告可释放配额或物理空间。

当前实现为 `SkillDirectoryCompactionService.retention_preview(user_id, expected_plan)`：
先在用户读锁内完整重建并比较整理计划，再使用同一固定时间计算 before/after 闭包。
结果包含仅预览有效的稳定虚拟 checkpoint（含原始身份映射）、原历史预计等待以及
`newly_released`。图预算继续生效，虚拟身份与既有 checkpoint 碰撞时整体拒绝。
没有新表、迁移、公开路由或 CLI 命令。此阶段没有模拟历史内容退役，因此依赖检查
仍须读取完整原历史；不能把 `newly_released` 直接当作 prune 选择或释放空间。

## 下一步需保留的内容入口边界

当前 `SkillContentObject.status` 已有 available/deleting，但对象主键含 category，磁盘
文件只有 user/digest。仅在当前 category 调用 `_validate_stored` 不足以阻止另一 category
在物理删除期间复用文件。未来持久化删除任务必须提供共享 user/digest 屏障，并覆盖
begin、prepare_file、put_file、complete、只读额度预检和所有已有树引用入口；已提交上传
的 complete 快速返回也不能绕过屏障。原不可变操作回执查询则不能因内容已退役而丢失。

已有上传过期收集器会按两个分类的登记摘要及活动上传保留文件；未来删除任务运行期间
必须继续保留 deleting 对象或显式纳入任务屏障，不能让该收集器越过持久化标记协议。
0042 已补齐完整树的真实等待时钟、跨分类 deleting 准入检查及实际历史内容外键库存，
见 `skill-tree-retention.md`。原 complete 重放不会刷新时钟；未绑定树不自动归属某个账户。
0043 已提供内部精确引用释放、分类结算、持久化标记和独立事务 worker，见
`skill-content-gc.md`。公开 prune 仍须把完整账户选择、整理、原请求回执和该层接成一个
业务提交；不能把内部精确计划接口当作已提供公共幂等命令。

投影验证包括与真实整理发布的完整图（根、全部保护理由、对象、当前成员）对比：普通
移除、链接 no-op、跨目录纯成员传播、精确成功迁移基线、活动 snapshot 和旧未知 backing。
活动 snapshot 测试通过正常 reset 建立新版分支后预约会话；原始 helper checkpoint 与完整
backing 在当前 head 被替换后仍受保护。共享文件上传与归档期限也有独立案例。

## 完整历史依赖计划

现有退役依赖检查已统一为有界、有方向的 retained-history 图。边表示消费者
承诺某个精确输入仍可恢复；从用户选定身份反向展开消费者闭包，保留目录成员/backing
形成的环。普通 parent、原不可变回执和已退役比较不构成此类依赖。snapshot 的收尾和
finalization 的发布也参与同一闭包。包版本和本地初始版本不属于 state 退役范围。

内部只读预览应列出原选择、连带消费者、全部依赖边、每项真实保护/等待情况及阻断。
整理后的预览使用现有只读投影和预计时钟；新增虚拟目录仍引用旧成员时必须显示无法
退役的替代引用，不能把虚拟身份也加入删除。活动 migration 输入上传须按固定时间查询
完整集合。所有者/账户/初始选择错误整体拒绝；资源上限整体失败，不返回部分计划。

内部原子执行只能接受同用户完整计划，在同一锁/保存点重建并精确比较后执行完整选择。
退役不再以 1000 条分批成功，使用与引用索引一致的一百万身份安全上限；全部依赖校验
仍在任何修改前完成。该上限不是容量验收。此步骤不创建公开操作回执、不结算配额或
删除文件；公开 prune 仍需把这些动作与整理、持久化请求及删除任务接入一个提交边界。


当前内部 `SkillHistoryRetirementPlanner.preview/apply` 和整理服务的 `retirement_preview`
已接入上述完整依赖计划。具体入口、阻断和重试限制见 `skill-retention.md` 的“完整历史
依赖计划与执行”。依赖闭包保留连带消费者的全部输入边用于重验，不通过正向输入关系
扩张退役目标。选择与整份计划仍是服务内结构；公开 CLI 请求不能直接序列化这个大集合。

完整依赖计划阶段的最终 Server 门禁为 1182 passed、28 skipped、81.14% coverage；
Ruff、Mypy（421 文件）、文档串与空白检查均通过：
`/tmp/skill-history-plan-server-quality.log`。PostgreSQL 三十九例含两个新增计划/pin 真锁
竞争，详见 `skill-retention.md`。公开选择/确认/回执、树和对象引用结算及两阶段物理 GC
仍未接入；这些测试不代表完整 Skill 管理器或真实运行后端已经验收。

## 0043 之上的只读空间预览与公开确认

0043 的基础内容 preview 读取当前真实树外键和对象边。其上的整理服务现已另行投影
本次已确认历史内容外键的解除，以及新等价树对原对象的引用；不能在
数据库中临时执行退役/整理来取得“预计”释放，也不能漏掉新目录仍使用的旧文件。
预计分类额度与待物理删除字节复用实际结算规则，并与变更后同锁重建的结果比较。
内部组合入口和已验证边界见 `skill-prune-projection.md`；公开选择与回执仍未接入。

账户候选、截止截点和确认摘要必须保持稳定。执行不能因等待确认期间又有历史到期而
自动扩张恢复损失；新上传、新引用或原计划变化需要拒绝旧确认。预计新释放时间与真实
提交事件时间不同，摘要应明确区分原始重验事实和仅供展示的预测时间，不能把动态扫描
时间当作永远重验失败的计划身份。CLI 仍需完整展示或遍历全部损失，持久化请求只携带
规范范围、固定选择边界和摘要，不把大清单塞进 4 MiB 请求日志。
