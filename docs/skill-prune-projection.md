# 整理、历史退役与实际内容结算的只读组合

本层完成公开 prune 的存储计划前置条件，不代替公开账户候选、确认摘要或原请求回执。

## 完整整理边界

精确整理选择及受保护目录视图不再受独立 1000 条边界限制，改用与完整保留索引一致的
一百万身份安全预算。完整清单仍有一百万总条目预算，单树仍受发布策略限制；超限整体拒绝。
整份选择只生成一个计划并在一个保存点发布，不按批次提交。按 backing 预建保留根索引，
不在每个目录反复扫描全部受保护 head 或重建全部选择集合。该上限不是容量验收结论。

## 内容投影

在用户读锁内重建精确整理计划、原历史保护和完整反向消费者闭包。历史计划有阻断时
不返回可执行内容回收计划，不能把其中容易退役的部分计成释放。无阻断时，按实际树引用
库存将选中 checkpoint/snapshot/finalization/publication/migration 的内容外键投影为已解除，
包括 publication 的复合选择和 migration 的复合人工授权。包和本地初始版本不被隐式删除。

新等价 checkpoint 对既有同摘要树的引用，以及新树对所有原对象的边都必须纳入投影。
按整理前后硬保护变化预计树等待；刚解除保护从分析时刻开始预计，未知旧时钟不补造。
只考虑确实被本次历史退役解除过外键的状态树，保留其完整剩余引用和截止诊断；其他账户
的历史、原始包及未绑定上传树不会被自动选入。未满足保护/外键/等待条件的树保留，不能
因为历史可以退役就声称它的配额也可以释放。

预计额度复用真实内容结算规则，并额外注入新树对象边。共享的另一分类、剩余树和所有
类别有效上传都保留，零预留租约规则不变。结果只表示预计分类释放与待物理删除字节。
所有虚拟 UUID 只用于展示引用，无 ORM 修改、上传、时钟、任务或配额写入。

## 内部组合执行

内部精确组合入口先用原分析时刻完整重建并比较原计划；原始事实、保护、外键或选择变化
使整份计划失效。分析时刻不能来自未来，不能用当前扫描重新扩大旧选择。全部历史阻断
检查先于任何实际整理。

一个外层 retention_mutation 保存点依次发布等价视图、退役完整历史、重建真实内容计划并
与预计动作比较，然后执行真实树/额度/任务结算。动作比较包含精确树集合、分类对象、
剩余树边、上传租约、分类字节和物理待删字节；仅预计树释放时间可与真实事件时间不同，
原时钟已在开始时重验。任何不一致或注入异常使 head、历史、额度和任务一起回滚。
独立 worker 仍只能消费最终提交的任务。

普通模式不能立即退役整理后刚释放的等价视图；这样的完整请求明确阻断而不悄悄部分
执行。公开候选层仍需把本次可执行的完整依赖组、仅需整理以启动等待的动作和保留原因
明确展示并纳入确认。内部组合 apply 不是公共幂等端点。

## 已实现入口与验证边界

`SkillDirectoryCompactionService.reclamation_preview` 返回精确整理、完整连带历史损失、
受影响树的剩余外键，以及可执行内容计划；历史仍有阻断时内容计划为空。
`apply_reclamation` 固定使用原预览的 `analyzed_at`，拒绝无时区和未来时间，并完整重验。
两者均为内部 API；不写公共请求记录、不承担中断恢复或原键重放。

真实发布中的原上传输入和已发布视图可能共享同一内容树，但不必属于同一反向消费者
闭包。只选择发布后旧 head 时，整理与历史退役可以成功而释放为零。调用方必须显式
选定相应原输入并展示完整损失，不能按摘要把剩余消费者自动加入删除范围。

验证覆盖新树对象边、同分类零预留上传、跨分类上传、未绑定完整上传保留、原输入剩余
外键、整份历史等待阻断、pin/消费者变化、超过一千项的精确选择、最后任务 flush 后
异常及外层回滚。预览用完整用户业务表列值指纹和 ORM 变更集合验证没有写入。
PostgreSQL 17 已迁移到 0043 的 48 项相关用例通过；四项真实连接竞争证明未提交 pin/
零预留上传持锁时组合必须等待，提交后拒绝旧预测，回滚后才允许原组合。
