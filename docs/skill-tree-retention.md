# 完整树等待时钟与删除前校验

这是 state prune 和物理 GC 的树时钟与准入契约。0043 已实现的内部引用释放、额度结算和
持久化删除 worker 见 `skill-content-gc.md`；公开 prune 仍需独立接入。

## 0042 树释放时钟

`skill_stored_trees` 新增可空 UTC `retention_released_at`。所有者/category/digest 主键、
完整清单、字节数、对象引用与历史外键保持不变。升级不回填旧树；降级在任何真实树
时钟存在时拒绝，不能丢弃释放证据后继续使用旧 GC 规则。

成功的新 complete 为尚无硬保护的完整树记录新的等待起点，覆盖未绑定历史的完整上传。
新上传复用已有树也代表新的真实内容交付，可重新开始无保护等待；同一已完成上传的
complete 重放及状态读取不刷新时钟。存在硬保护时无可用截止。引用事务继续使用统一
用户锁/保存点：获得保护清空时钟，最后解除硬保护启动时钟，单纯退役已解除保护的历史
不重新启动等待，避免历史期限后再无条件等待一次。未知旧证据保持 NULL，不能从扫描、
创建时间或部署时间补造。没有硬保护也不意味着可以忽略尚保留的真实历史外键。

独立无引用树默认使用 history_days；包含归档历史的内容仍受各原始历史的 archive_days
和完整依赖检查约束。普通清理必须同时满足树截止与全部历史内容引用释放。提前模式
只能在明确审阅的精确内容范围内越过等待，不绕过当前树、活动输入或其他 retained 历史。
未绑定任何状态历史的完整树不自动成为某个账户的 state prune 目标，需独立的用户范围
过期清理或明确选择。原上传状态仍可查询，但已回收树的 complete 内容重放返回过期。

## 实际树引用库存

内部只读 `SkillRetentionInspector.trees(user_id, policy)` 返回每个分类树的硬保护理由、
真实释放时间、可证明截止和所有仍生效的历史内容外键。引用记录保留来源表、完整主键、
实际内容列和账户归属；包原始版本不伪造账户归属。迁移人工内容使用
`(migration_id, tree_digest)`，冲突选择使用 `(publication_id, selector_key)`，不能只报单个 UUID。

库存显式对应 11 个真实历史摘要列，包括 snapshot、finalization、publication、迁移三侧、
冲突选择及迁移人工授权的生成保留列。退役后生成列变为 NULL，库存随真实外键解除而变化，
原始摘要和授权主键仍保留。每次索引加载同时核对 ORM 元数据中的全部树摘要外键；新增未分类
表或在已分类表上新增摘要外键都整体拒绝分析。树到对象的内部引用单独登记，不能混成历史消费者。

历史外键是独立于硬保护与树截止的保留约束。归档历史的树即使已过普通树等待期，仍不能越过
其 90 天历史等待和实际 retained 外键。此库存不返回删除授权或预计回收字节数。

## 共享文件准入

磁盘文件按 user/digest 共享，category 只是额度分类。所有新上传、文件授权、put、complete、
状态配额预检、完整树/文件读取和已有包摘要引用必须检查同用户所有分类的 deleting 标记。
begin 的原键元数据重放、get 和原操作回执读取不授予新内容引用，可继续查询原受理。
检查与实际写入/引用建立共用用户锁；不能只检查当前 category 然后复用另一分类正在删除
的同一文件。旧暂存收集器保留所有已登记对象，包括 deleting，不能越过未来持久化删除任务。

0042 的时钟/准入层本身不创建 deleting 标记或删除文件。后续 0043 已提供真实树/对象
引用释放、类别结算、持久化删除重试和 worker 生命周期，具体事务及测试边界见
`skill-content-gc.md`；共享文件存在仍不代表已经退役的树可恢复。

## 后续结算与 worker 必须保留的约束

同分类有效上传可能因为对象已存在而只预留零字节。解除最后一棵树的引用后，若还有
同分类有效上传引用该对象，不能直接删分类对象或扣减其使用量，再让原 complete 以零预留
增加使用量。首个结算实现应保留该分类对象与计量，直到这些有效租约结束；不能只看
`reserved_bytes > 0`，也不能把物理文件尚在等同于已经预留了该类别额度。

另一分类的保留树或活动上传保护底层文件，但不自动阻止本分类在无引用、无有效租约后
解除自己的对象与额度。只解除一个类别时，不得给仍在使用的共享文件设置全局删除屏障。
最后一个物理保留理由消失后，才允许在同一用户事务内记录持久化删除任务和 deleting 标记。
逻辑释放、仍被另一类别保留的物理字节、待物理删除字节须分别解释，不能把分类额度减少
当作磁盘已减少。重试不得重复扣减额度。

worker 执行每个删除动作前需在用户锁内验证确切任务身份、标记及全部跨类别引用/租约。
旧任务不能只凭摘要去删除后来重新完整上传的同名文件。锁和持久化屏障必须覆盖磁盘动作
实际结束；取消协程不代表磁盘线程已停止。既有 `run_storage_io` 会等待线程退出后才传播取消，
后续删除应保留这一生命周期保证。已 unlink 而数据库尚未提交时继续保留持久化屏障，
重试把文件不存在视为可收敛状态；不得先开放新上传再让旧删除任务补做磁盘动作。

上述约束由 0043 的模型/迁移、事务及故障测试实现，另以卷内原任务回执和 flock 覆盖
数据库连接丢失后的迟到磁盘线程。下方是较早的 0042 验证记录；当前回收证据见
`skill-content-gc.md`。
